# 界面（学习者 SPA）

面向"要改前端 / 要判断排版好不好"的人。三栏怎么分、题面怎么渲染、哪些信息折叠——本文一次讲清。

## 三栏，按用途分而不是一路往下堆

| 栏 | 放什么 | 为什么 |
|---|---|---|
| 左（sticky） | 阶段看板 + 通关进度 | 读长题面时"我在第几关"不该滚出屏幕 |
| 中（`main.doc`） | **文档阅读区**：题面 → 你的改动 → 阅卷报告 → AI 评审 → 判定结论 | 中栏只负责"读"。正文限宽 880px（约 74 字符），长句不需要来回扫行首 |
| 右（sticky） | **操作面板**：开始 / 提交 / 发起评审 / 取结论 / 返工 / 进入下一题，外加当前实例与历史 | 所有会改动状态的动作集中一处；读的时候视线只在"选阶段"与"点下一步"之间切换 |

窄屏（≤1279px）收成两栏，≤899px 收成一栏。

文档区的每一节都用同一个壳（标题 + "这一节回答什么"），题面内部再按作者写的 Markdown 分小节
（本关速览 / 任务说明 / 改动面 / 验收标准 / 提示）。**"现在能做什么"的规则只有一份**
（`src/actions.ts::deriveActions`）：操作面板按它渲染按钮，文档区不会自己长出第二套判断。

## 动作的显隐规则

- 只渲染**此刻真能点**的动作：已通过的阶段上不会挂着三颗灰按钮（真踩过——那只会让人以为漏点了什么）；
- 唯一例外是「取确定性结论」：它带着"还缺什么"，而"门要证据齐了才开"正是学员该看懂的一件事；
- 低频且**有副作用**的动作（`从远端同步` 会 fetch 并可能快进后端那份 checkout）收进折叠区；
- 「重做这一题」是作废性动作，走两步确认，并把"**它不会动你的代码**"写在确认块第一句。

## 题面渲染（Markdown + TeX）

Track 作者本来就是按 Markdown 写 `brief.problem` 的（`**加粗**`、`` `内联代码` ``、`1) 2)` 列表、
缩进代码块），当纯文本直出时记号原样露出、换行被折叠，整段糊成一坨。于是渲染前做三层处理：

1. **marked + GFM**（`breaks: true`）：段落、列表、代码块、表格、引用；
2. **CJK 排版规范化**：中文题面常用单换行做有意义的换行（`①②`、`【线上问题｜…】`），又常为了在
   YAML 里好看而在句中硬换行——纯 Markdown 只能二选一（全接起来丢结构 / 全断开把句子劈成两半）。
   所以按标点与形状判断该接的接、该断的断，并把缩进的类代码块明确围栏起来（否则列表项里的 SQL
   会散成普通段落）；
3. **KaTeX** 渲染 `$…$`：只在文本节点里替换，跳过 `code`/`pre`，所以 SQL 里的 MyBatis `${…}`
   不会被当成公式。

内容可能来自**社区贡献的 Track**（`trust_level: community`），所以渲染结果一律经 DOMPurify 消毒
（`marked` 也已关掉原始 HTML）。代价：这三个依赖（marked / katex / dompurify）让前端 JS 产物从
~250 KB 涨到 ~612 KB（gzip 190 KB）——自托管单用户场景下不值一提，介意的话可以按需拆包。

> 题面本身的**写法**也是一等公民：`brief.problem` / `grader.correctness.expect` / `hints` 会被渲染成
> 一个有层级的页面，所以 Track 作者要按内容规范写（叙事优先，别"一句话一个 Card"）——规范正文在本仓
> [`工单写作规范.md`](工单写作规范.md)，内容仓只放指针、不复制第二份。

```bash
cd frontend

npm run ui:clips      # 1:1 局部（题面 / 判据 / 提示 / 历史），判断排版质量用这个
```
